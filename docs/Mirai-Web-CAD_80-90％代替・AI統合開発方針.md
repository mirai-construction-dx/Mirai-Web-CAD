# Mirai Web CAD 80～90％代替・AI統合開発方針

更新日: 2026-08-30  
対象: Mirai Web CAD  
目的: AutoCAD／ARES Standardの実務代替率を、建設・土木向けの限定ワークフローにおいて80～90％まで引き上げるため、現状評価、製品原則、AI安全設計、CAD機能、開発順序及び合格基準を一つの方針として定める。

> **2026-08-30追記**: DWG対応を正式に本方針から撤回し、DXF単体運用へ確定した([ADR-0002](adr/ADR-0002-dwg-scope-drop-dxf-only.md))。本文中の「DWG」関連記述はDXFへ統一済みである。本方針転換を踏まえた代替率数値の再評価は次回監査サイクルで実施する(本改定では数値の再算定を行っていない)。

---

## 1. 結論

Mirai Web CADの現状の実務代替率は、AutoCAD／ARES Standard全体に対して**30～35％、代表値32％前後**と評価する。

一方、代替対象を次の土木2Dワークフローに限定すれば、**80％は現実的であり、90％も条件付きで到達可能**である。

> 土木2D施工図の受領 → 内容確認 → 修正 → レビュー・承認 → 尺度保証PDF／DXF返却 → 版・監査保存

本方針は、AutoCAD／ARES Standardの全画面・全コマンドを再現することを目的としない。3D、BIM authoring、レンダリング、機械・電気専用CAD、LISP完全互換まで含む全製品代替は対象外とする。

優先順位は次のとおりとする。

> DXF往復・精密CAD Core・尺度保証PDF  
> → 案件権限・版・レビュー・性能・復旧  
> → AI作図・照査支援  
> → 土木計算・設計支援  
> → 建設土木AI CADプラットフォーム化

AI機能を先に広げるのではなく、正式図面を安全に受領・編集・返却できるCAD基盤を先に完成させ、その上にAIを載せる。

## 2. 80～90％代替の定義

### 2.1 80％代替

80％到達とは、実案件100図面において、主要図形、座標、レイヤー、文字、寸法、ブロック、レイアウト及び印刷結果の95％以上が許容差内で保持され、主要利用者がAutoCAD／ARES Standardを起動せずに対象業務を完了できる状態をいう。

80％の必須範囲は次のとおりとする。

- DXFの読込・編集・書出し
- 主要2D図形と精密編集
- 寸法、文字、ハッチ、ブロック、レイヤー
- レイアウトと尺度保証PDF
- 案件・図面権限
- 版、差戻し、承認、監査
- 大規模図面の実用性能
- クラッシュ復元とバックアップ
- 土木施工図の基本テンプレート

### 2.2 90％代替

90％到達には、80％の条件に加え、次を必要とする。

- 外部参照XREF
- 複数レイアウト及びSheet Set相当
- 図面比較
- JGD2011／JGD2024及び平面直角座標系
- 電子納品検査
- GIS／BIM参照連携
- 協力会社レビュー・配布・受領確認
- オフライン閲覧・朱書き
- 100,000図形級の実用性能
- オフサイトバックアップ及びDR実測
- 実案件100図面以上の継続的な互換認定

### 2.3 意図的な対象外

- 高度な3Dモデリング
- BIM authoring全般
- レンダリング
- 機械・電気専用CAD機能
- AutoLISP／ARX等の完全互換
- AutoCAD全業種向け機能の網羅

## 3. 現状評価

### 3.1 現状代替率

| 業務領域 | 現状代替率 |
|---|---:|
| 簡単な2D図面の新規作成 | 35～45％ |
| 精密な日常2D編集 | 20～30％ |
| 既存DXFを開いて修正しDXFで返却 | 5～10％ |
| 尺度保証PDF・正式成果物 | 10～20％ |
| レイヤー・基本UI・コマンド操作 | 40～50％ |
| 単一管理者によるレビュー・監査 | 50～60％ |
| 複数利用者・案件権限管理 | 20～30％ |
| 大規模図面性能 | 20～30％ |
| 土木固有業務 | 15～25％ |
| **総合** | **30～35％** |

運用基盤は前進しているが、代替率を決定するDXF往復、精密編集、レイアウト、PDFの深さはまだ不足している。

### 3.2 現在の強み

- LINE、RECT、CIRCLE、PLINE、TEXT、簡易DIM／HATCH／BLOCK
- MOVE、COPY、ROTATE、SCALE、OFFSET、TRIM、EXTEND
- PAN、ZOOM、DIST、AREA、ID、Undo／Redo
- レイヤー作成、表示、ロック、色、線幅
- 決定論的CAD CoreとAI提案処理の分離
- AI変更のプレビューと人による承認
- Viewer／Drafter／Reviewer／Approver／CAD Adminの能力モデル
- 楽観ロック、Idempotency-Key、改訂番号
- 監査ログの追記専用化
- API未接続時の承認禁止
- Cloudflare Accessによる書込み保護
- ローカルPostgreSQLへの原子的保存
- CI、PostgreSQL統合試験、バックアップ／復元試験
- 合成監視と障害Issue起票
- viewport外図形の描画省略

Web配布、承認、監査、AI変更履歴は、従来CADとの差別化に利用できる。

### 3.3 最大の不足

#### DXF往復

- DXF書出しなし
- ARCをポリラインへ変換
- HATCH、DIMENSION、INSERT、BLOCK、XREF、layout、plot style等を保持できない
- 出力はMirai JSONのみ

現在は「既存DXFを受領し、修正後にDXFで返却する」業務が成立していない(DXF書出し未実装のため)。

#### 精密編集

- TRIM／EXTENDは境界交点演算ではなく線端の座標移動
- ポリラインOFFSETは真正な平行曲線ではなく重心基準の放射移動
- 単一選択のみ
- 窓・交差・複数選択、選択フィルタなし
- グリップ編集なし
- 中点、交点、垂線、接線、近接点OSnapなし
- FILLET、CHAMFER、MIRROR、ARRAY、STRETCH、BREAK、JOIN、EXPLODEなし

見た目が近くても、座標や寸法に誤差が生じるおそれがあるため、現状の精密編集を正式成果物へ使用してはならない。

#### 寸法・ハッチ・ブロック

- 寸法は2点間の簡易寸法が中心
- 角度、半径、直径、座標、公差、連続寸法なし
- 寸法スタイル、連想更新なし
- ハッチの島、閉領域探索、連想更新なし
- ブロック定義と参照が未分離
- 複数図形ブロック、再定義、分解、属性定義、ライブラリなし

#### レイアウト・PDF

- 用紙設定UIはあるが、viewportへ実図形を描画していない
- 印刷は`window.print()`依存
- 実尺度、線幅、線種、日本語フォントを保証できない
- CTB／STB相当なし
- 複数viewport、尺度固定、バッチ印刷なし

#### 性能

- viewportカリングは存在するが、全図形を走査するO(n)処理
- hit-testとOSnapに空間インデックスなし
- 10,000図形試験はCAD Core処理であり、Canvas FPS試験ではない
- 100,000図形／30fpsは未計測

#### ライブUI

- 閲覧者でも新規、保存、作図、移動、削除等のボタンが有効
- A4選択とA3横プレビューが同時に表示される場合がある
- 「保存先: このブラウザ」と「API同期済み」が併記され、正本が不明瞭
- 390px幅では固定領域がCanvasを覆う
- 閲覧者の選択・計測・プロパティ参照の導線が不明瞭
- 寸法、ハッチ、PDF、同時編集は実案件相当のライブ検証が未完了

## 4. 製品ビジョン

現在公開しているMirai Web CADの基本機能とWeb環境を土台として、単なるCAD機能の再現ではなく、**従来CADの操作性とAIによる作図・設計支援を統合した、建設・土木向けWeb CAD**として開発する。

### 4.1 基本原則

- CAD経験者にAI操作を強制しない
- 初心者に複雑なCADコマンド習得を強制しない
- AIを使用しなくても主要CAD業務を完結できる
- AIは候補、説明、作図命令、修正提案を担当する
- 数値計算と幾何処理は検証済みの決定論的処理を使用する
- AIは正式図面を自動確定しない
- 最終判断と正式承認は技術者が行う
- 図面、計算、資料、命令、変更、承認の対応関係を追跡する

### 4.2 基本ワークフロー

```text
資料投入
  ↓
AIによる条件候補の抽出
  ↓
不足・矛盾条件の提示
  ↓
技術者による条件確定
  ↓
ルールによる計算ケース生成
  ↓
検証済みソルバーによる計算
  ↓
AIによる構造化CAD命令の生成
  ↓
CADエンジンによる作図プレビュー
  ↓
決定論的検査＋AIによる説明
  ↓
技術者レビュー
  ↓
修正提案の承認・却下・保留
  ↓
技術者による最終承認
  ↓
正式図面化・版固定・監査保存
```

## 5. AIとCADエンジンの責任境界

### 5.1 AIに任せてよい処理

- 資料からの条件候補抽出
- 不足項目に関する質問
- 矛盾候補の提示
- 計算ケース候補の整理
- 構造化CAD命令候補の生成
- 計算結果の説明
- 図面不整合候補の説明
- 修正案及びコメント下書き
- 仕様書・過去図面の検索補助

### 5.2 AIに任せない処理

- 正式な寸法値の決定
- 座標変換の確定
- 構造計算そのもの
- 数量の正式確定
- 安全率や適用基準の変更
- 権限判定
- 電子納品の正式合否
- 正式図面への昇格
- 発注者・協力会社への外部提出

これらは、検証済みルール、ソルバー、CAD Core及び権限者承認で処理する。

### 5.3 AI作図命令

AIは図面データを直接書き換えず、原則としてCADエンジンへ構造化命令を渡す。

例:

- 延長20mの擁壁候補を作図
- 中心線から左右3.5mに道路端線候補を作成
- 500mm間隔で寸法線候補を配置
- 選択線を5m延長
- 選択図形を500mmオフセット

各命令には次を記録する。

- 指示者
- 自然言語入力
- 構造化命令
- 対象図形ID
- 実行前後の差分
- CAD Coreの実行結果
- 検査結果
- 承認者及び承認日時
- AIモデル、プロンプト及びツールの版

### 5.4 情報の状態区分

AIが抽出した条件には、必ず次の状態を付ける。

- 原文確認済み
- AI抽出・未確認
- 技術者確認済み
- 推定値
- 不足
- 矛盾あり
- 使用禁止
- 正式確定

AI抽出という理由だけで計算や作図へ使用してはならない。技術者確認済み又は正式確定の条件だけを正式処理へ渡す。

### 5.5 根拠情報

各条件には次を保持する。

- 元資料ID
- ファイル版
- ページ番号又は図面位置
- 抽出文字列
- 抽出日時
- AIモデル・プロンプト版
- 信頼度
- 確認者
- 確認日時

### 5.6 資料アップロードの安全性

- マルウェア検査
- ファイルサイズ・形式制限
- 案件ACL適用後にAIへ送信
- 外部URLの自動取得禁止
- 文書内の記述をAIへの命令として実行しない
- ブラウザ及び配布ソースへAPIキーを置かない
- AI事業者への学習利用禁止設定
- 保存期間及び削除方針
- 入力資料、AI出力、人の修正及び承認の監査ログ
- Prompt Injectionを前提としたtool allowlist及び出力schema検証

## 6. CAD UI方針

### 6.1 基本コンセプト

- AutoCAD／ARES Standard利用者が大きな違和感なく操作できる
- CAD経験者向けと初心者向けのワークスペースを分ける
- 従来CAD操作とAI操作の双方を提供する
- AIパネルを閉じても全CAD操作を利用できる
- 画面の大部分を作図Canvasとして確保する
- 操作回数を抑え、キーボード中心の高速操作にも対応する

### 6.2 基本配置

- 中央: メイン作図領域
- 上部: ホーム、作図、修正、注釈、画層、計測、AI、出力
- 左右: プロパティ、画層、AI、資料、検査結果をドッキング可能なパネルとして配置
- 下部: CADコマンドライン
- ステータス領域: 座標、尺度、スナップ、直交、選択数、保存・同期・競合状態

左右パネルの配置、幅、表示状態は利用者設定として保存する。2画面・3画面利用では、複雑なドッキングより先に、AI、資料、プロパティを別ウィンドウで開く方式を検討する。

### 6.3 CAD経験者向け

- AutoCAD互換presetとMirai preset
- 管理者設定可能なコマンドエイリアス
- キーボードショートカット
- 右クリック操作
- コマンド履歴と再実行
- オートコンプリート
- 相対座標、極座標、ダイナミック入力

### 6.4 初心者向け

- アイコンとツールチップ
- 日本語によるAI操作
- 選択図形に応じた操作候補
- 禁止操作の理由表示
- 実行前の対象図形数と変更差分
- 承認、却下、保留の明確な選択

### 6.5 権限UI

- 閲覧者には選択、計測、プロパティ参照、コメントを許可する
- 閲覧者の作図、移動、削除、保存、初期化は無効化する
- ボタンを無効にするだけでなく、権限不足の理由を表示する
- UI制御に加え、API側でも必ず403又は相当のfail-closed制御を行う
- サーバ正本、ブラウザ一時保存、未同期、同期済み、競合、オフラインを常時表示する

### 6.6 モバイル

モバイルではフルCAD編集より、次を優先する。

- 閲覧
- 計測
- 朱書き
- コメント
- 写真・位置の紐付け
- レビュー
- 承認
- 配布・受領確認
- オフライン閲覧

## 8. 本番データ・運用方針

### 8.1 現行正本

本番の正本データベースは**ローカルPostgreSQL 16**とし、Cloudflare Tunnelを経由して提供する。Neonを現行本番構成へ再導入しない。

確認済みの現行状態:

- 本番`/api/health`: 200
- DB provider: `postgres`
- DB mode: `connected`
- Migration: 適用済み
- アプリsystemd: active／running
- Cloudflare Tunnel: active／running
- 未認証書込み: Cloudflare Accessへ302
- 日次バックアップ及び鮮度確認timer: active

### 8.2 ブラウザ保存

ブラウザ保存は一時キャッシュとして扱う。

- サーバ正本
- ローカル一時保存
- 未同期
- 同期済み
- 競合
- オフライン
- 復元可能

これらをUIへ明示する。LocalStorage平文から、暗号化IndexedDB及び差分autosaveへ移行する。

### 8.3 旧Pages／Neon系統

旧`mirai-web-cad.pages.dev`のFunctions及びNeon接続は現行本番ではない。Custom Domainを正本として安定監視した後、旧Pages Functions、旧環境変数、旧Neon Projectは人の承認を経て廃止する。

### 8.4 運用継続性

- オフサイトバックアップ
- 本番dumpから隔離DBへの復元試験
- RPO／RTO実測
- ホスト停止、ディスク故障、回線断の訓練
- ロールバックSHAの記録
- build、restart、health、rollbackを含む承認型デプロイ
- PostgreSQL統合テストをbranch protectionの必須checkへ追加

## 9. 開発ロードマップ

### Phase 0: 代替対象・合格基準・互換コーパス

目安: 2週間  
代替率目標: 32％を正確に測定できる状態

- 対象業務を土木2D施工図の受領・修正・レビュー・PDF／DXF返却へ固定
- 実案件100図面を収集
- 20図面を開発回帰、80図面を最終UATへ分離
- entity、座標、layer、block、文字、寸法、layout、線種、印刷の採点方法を決定
- 未対応entityを黙って破棄しない方針を確定
- 80％、90％及び対象外を明文化
- 現行UIの閲覧者権限、A4／A3不一致、保存正本表示を修正
- 最新mainの本番反映手順を確立
- `state.json`のテスト件数とblocker数をCI証拠から同期

完了基準:

- 100図面の台帳と利用許諾が存在する
- 比較器と採点表が存在する
- 未対応entityが無通知で消失しない
- 実装済み／限定対応／計画の表示が最新状態と一致する

### Phase 1: CAD正本・精密編集・成果物

目安: 2～4か月  
代替率目標: 55～70％

- 内部CADモデルへARC、ELLIPSE、SPLINE、INSERT、DIMENSION、HATCH、LEADER、layoutを追加
- DXF書出し
- Import→Export→再Importの構造比較

## 14. 最終判断

Mirai Web CADは、汎用CADの全機能を追いかけるのではなく、次の組合せで独自価値を形成する。

- AutoCAD／ARES Standard利用者が扱える2D CAD操作
- 実案件DXF互換
- 正確な幾何編集と尺度保証成果物
- Webによる配布、レビュー、承認及び監査
- 人が最終判断するAI作図・照査支援
- 土木座標、数量、縦横断、電子納品等の専用機能

この順序を守れば、土木2D施工図の限定ワークフローにおける80％代替は現実的である。90％にはXREF、複数レイアウト、土木座標、電子納品、協力会社運用、大規模図面性能及びDR実証が必要となる。

CAD正本と成果物を完成させずにAI機能だけを増やすと、「賢いが正式図面を返せないCAD」になる。CAD基盤を先に完成させ、その上へAIを載せることを本開発の最重要原則とする。
